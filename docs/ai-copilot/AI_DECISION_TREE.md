# แผนผังการตัดสินใจ (AI Decision Tree) — POS Today Copilot

> เอกสารนี้คือ "สมุดคู่มือการตัดสินใจ" สำหรับเจ้าของร้าน เมื่อ Copilot (ผู้ช่วยอัจฉริยะ) แจ้งเตือนปัญหาหรือโอกาส
> แต่ละแผนผังจะพาคุณจากสัญญาณที่เห็น → คำถามที่ต้องถามตัวเอง → ปลายทาง (leaf) ที่เป็น **ขั้นตอนถัดไปที่ทำได้จริงในเมนูของระบบ**
>
> **วิธีอ่าน:** เริ่มจากบนสุดของแต่ละต้นไม้ ตอบคำถามทีละข้อ แล้วเดินตามกิ่งจนถึงปลายทางที่มีสัญลักษณ์ `→ ไปที่เมนู ...`
>
> **ขอบเขตของ Copilot (อ่านก่อนใช้งาน):**
> - Copilot **ตอบจากข้อมูลที่คำนวณไว้ล่วงหน้า** (ภาพรวมสุขภาพร้าน, สต็อก, ลูกหนี้, ความเสี่ยง) ไม่ใช่ AI ที่พิมพ์ตอบอิสระ
> - Copilot **สั่งงานแทนไม่ได้** เช่น สร้าง PO / ปรับสต็อก / รับชำระเงิน — ต้องไปทำเองในเมนูที่ระบุ (ฟังก์ชันสั่งงานยังขึ้นว่า "เร็ว ๆ นี้")
> - ข้อมูลเป็นภาพรวม **วันนี้ และ 7 วันล่าสุด** เท่านั้น ขณะนี้ระบบยังไม่มีข้อมูลแนวโน้มย้อนหลัง 30 วัน / เทียบปีต่อปีในตัว Copilot

---

## สารบัญแผนผัง

1. สต็อกต่ำ / ใกล้หมด → เติมสต็อกอย่างไร (โอนคลัง vs สั่งซื้อ vs รอ PO)
2. ลูกหนี้ค้างชำระ → แบ่งตามอายุหนี้ → ทำอะไรต่อ
3. กำไรติดลบ / กำไรต่ำ → ต้นทุน vs ค่าใช้จ่าย vs ราคาขาย
4. สินค้าค้างสต็อก (Dead Stock) → ตัดสินใจระบายของ
5. สินค้าไม่มีราคาทุน (Missing Cost) → แก้ไขข้อมูล
6. ใบรับสินค้าค้างยืนยัน (Pending Goods Receipt) → ยืนยันเข้าคลัง
7. ภาพรวมสุขภาพร้าน → จัดลำดับว่าควรทำอะไรก่อน

---

## 1) สต็อกต่ำ / ใกล้หมด — ควรเติมสต็อกแบบไหน?

**สัญญาณจาก Copilot:** ถาม "สต็อก / ใกล้หมด / reorder" หรือดูการ์ดสุขภาพสต็อก (จำนวนสินค้าหมด `outOfStockCount`, สินค้าใกล้หมด `lowStockCount`, รายการเติมด่วน `urgentReorders`)

**ข้อมูลที่ Copilot ใช้:** จำนวนวันที่ของจะหมด (`daysOfStock`), สต็อกปัจจุบัน, ยอดขายเฉลี่ยต่อวัน, จำนวนแนะนำให้สั่ง (`reorderQty`), มี PO ค้างอยู่หรือไม่ (`hasPendingPO`) และ **คำแนะนำสำเร็จรูป** (`recommendation`: purchase / wait_for_po / transfer) พร้อมเหตุผลภาษาไทย (`reasonTh`)

```
มีสินค้าใกล้หมด / หมดแล้ว?
│
├─ Copilot บอกว่ามี PO ค้างของรายการนี้อยู่แล้ว (hasPendingPO = ใช่)
│   │  คำแนะนำของระบบ = "wait_for_po" (รอของเข้า)
│   └─► ขั้นถัดไป: อย่าเพิ่งสั่งซ้ำ — ไปตรวจสถานะใบสั่งซื้อ
│         → ไปที่เมนู จัดซื้อ › การสั่งซื้อ (/purchases) ดูสถานะ PO
│         → เมื่อของมาถึง: จัดซื้อ/คลังสินค้า › รับสินค้าเข้า (/warehouse/receive)
│
├─ Copilot แนะนำว่า "transfer" (มีของอยู่อีกคลัง/อีกจุด)
│   │  หมายถึงคลังหนึ่งมีของพอ แต่จุดที่ขายไม่มี
│   └─► ขั้นถัดไป: ย้ายของจากคลังที่มี มาที่จุดขาย
│         → ดูปริมาณคงเหลือแต่ละคลัง: คลังสินค้า › สต็อกสินค้า (/inventory)
│           (ตารางแยกตามคลัง/ตำแหน่งจัดเก็บ)
│         → ตรวจโครงสร้างคลัง: คลังสินค้า › คลังสินค้า (/stock/warehouses)
│         หมายเหตุ: ขณะนี้ระบบยังไม่มีหัวข้อคู่มือ "การโอนย้ายสต็อกระหว่างคลัง"
│         ในศูนย์ช่วยเหลือ ให้ทำผ่านหน้าสต็อก/คลังตามโครงสร้างที่มี
│
├─ Copilot แนะนำว่า "purchase" (ต้องสั่งซื้อใหม่) และยังไม่มี PO ค้าง
│   │
│   ├─ รู้ผู้ขายอยู่แล้ว
│   │   └─► ขั้นถัดไป: เปิดใบสั่งซื้อด้วยจำนวนที่ระบบแนะนำ (reorderQty)
│   │         → ไปที่เมนู จัดซื้อ › การสั่งซื้อ (/purchases)
│   │           กด "+ สร้างใบสั่งซื้อใหม่" → เลือกผู้ขาย → ใส่สินค้า+จำนวน → ส่ง PO
│   │
│   └─ ยังไม่มีผู้ขายผูกกับสินค้านี้ (ดูข้อ 8 — purchasingIntelligence
│       noSupplierProducts / singleSupplierProducts)
│       └─► ขั้นถัดไป: เพิ่ม/เลือกผู้ขายก่อน แล้วค่อยเปิด PO
│             → ไปที่เมนู จัดซื้อ › ผู้จัดจำหน่าย (/purchases/suppliers)
│               กด "+ เพิ่มซัพพลายเออร์" → ใส่ชื่อ, เลขภาษี 13 หลัก, เงื่อนไขเครดิต
│             → จากนั้นเปิด PO ที่ จัดซื้อ › การสั่งซื้อ (/purchases)
│
└─ อยากดูภาพรวมก่อนตัดสินใจทั้งหมด
    └─► ขั้นถัดไป: ดูสินค้าที่ต้องจับตา + กดสั่งซื้อรายตัว
          → ไปที่เมนู แดชบอร์ด (/dashboard) ส่วน "สินค้าที่ต้องจับตา"
            กดชื่อสินค้า → กด "สั่งซื้อ" เพื่อเปิด PO รายการนั้น
```

**กฎง่าย ๆ สำหรับเจ้าของร้าน:** มีของอยู่แล้วอีกคลัง → ย้าย (เร็ว/ไม่เสียเงินเพิ่ม) • มี PO ค้างแล้ว → รอ อย่าสั่งซ้ำ • ไม่มีทั้งสองอย่าง → สั่งซื้อ

## 2) ลูกหนี้ค้างชำระ — แบ่งตามอายุหนี้แล้วทำอะไร?

**สัญญาณจาก Copilot:** ถาม "ลูกหนี้ / ค้างชำระ / เก็บเงิน / overdue" หรือการ์ดปฏิบัติการ (`operations.overdueCreditCount`, `operations.overdueCreditAmount`)

**ข้อมูลที่ Copilot ใช้:** ยอดค้างรวม (`totalOutstanding`), ยอดเกินกำหนดรวม (`totalOverdue`), กลุ่มตามอายุหนี้ (`agingBuckets`: current / 30_60 / 60_90 / 90_plus) พร้อมจำนวนรายและยอดเงิน, และรายชื่อลูกหนี้เกินกำหนด (`agingCustomers`: ชื่อ, ยอดค้าง, กลุ่มอายุเก่าสุด, จำนวนวันเกินกำหนด)

```
Copilot แจ้งมียอดลูกหนี้ค้างชำระ?
│
├─ กลุ่ม "ปัจจุบัน" (current — ยังไม่เลยกำหนด)
│   └─► ขั้นถัดไป: ยังไม่ต้องเร่ง แค่จับตา
│         → ดูบิลค้าง: เอกสาร › บิลค้างชำระ (/documents/pending)
│         → หรือหน้า ขายเชื่อ / ยืม (/credit-sales) เพื่อเห็นวันครบกำหนด
│
├─ กลุ่ม 30–60 วัน (30_60)
│   └─► ขั้นถัดไป: เริ่มทวงอย่างสุภาพ + เตรียมรับชำระ
│         → ไปที่เมนู ขายเชื่อ / ยืม (/credit-sales) หาบิลของลูกค้า
│           กด "รับชำระหนี้" → ใส่ยอด + วิธีชำระ → ยืนยัน (สถานะเป็น "ชำระแล้ว")
│
├─ กลุ่ม 60–90 วัน (60_90)
│   └─► ขั้นถัดไป: ทวงจริงจัง + ทบทวนวงเงินเชื่อก่อนขายเชื่อรอบใหม่
│         → รับชำระที่ ขายเชื่อ / ยืม (/credit-sales) › "รับชำระหนี้"
│         → ดูข้อมูลลูกค้าประกอบ: ลูกค้า (/customers)
│         หมายเหตุ: ขณะนี้ระบบยังไม่มีเมนูตั้ง "วงเงินเครดิต/ระงับบัญชี"
│         ของลูกค้าโดยตรง ให้ใช้ดุลพินิจหยุดขายเชื่อรายนี้ชั่วคราว
│
└─ กลุ่มเกิน 90 วัน (90_plus — เก่าสุด/เสี่ยงสุด)
    └─► ขั้นถัดไป: ถือเป็นหนี้เสี่ยงสูง เร่งติดตามเป็นรายแรก
          → Copilot โชว์รายชื่อลูกหนี้เกินกำหนด (สูงสุด 3 ราย) เรียงตามวันเกินกำหนด
          → รับชำระเมื่อเก็บได้: ขายเชื่อ / ยืม (/credit-sales) › "รับชำระหนี้"
          → กรณีต้องลดยอดหนี้ (เช่น ตกลงคืนของ/ส่วนลด):
            ออกเอกสารที่ เอกสาร (/documents) — ใบลดหนี้ (Credit Note) เพื่อลดยอดค้าง
```

**ถามต่อกับ Copilot ได้:** พิมพ์ "ถ้าไม่ทำจะเป็นยังไง" เพื่อให้ Copilot อธิบายความเสี่ยงหนี้สูญ • พิมพ์ "ควรทำวันนี้ไหม" เพื่อดูระดับความเร่งด่วน (🔴 ทันที / 🟡 วันนี้ / 🟢 สัปดาห์นี้)

**กฎง่าย ๆ:** ยิ่งอายุหนี้มาก ยิ่งเก็บยากและเสี่ยงสูญ → จัดลำดับทวงจากเก่าสุด (90+) ลงมา

## 3) กำไรติดลบ / กำไรต่ำ — ปัญหาอยู่ที่ต้นทุน, ค่าใช้จ่าย หรือราคาขาย?

**สัญญาณจาก Copilot:** ถาม "กำไร / profit / ขาดทุน / margin" หรือการ์ดสุขภาพการเงิน (`finance.netProfit` ติดลบ/ต่ำ, `finance.netMargin`, `finance.grossMargin`)

**ข้อมูลที่ Copilot ใช้ (moneyIntelligence):** รายได้ (`revenue`), ต้นทุนขาย (`cogs`), กำไรขั้นต้น (`grossProfit`) + มาร์จิ้นขั้นต้น (`grossMargin`), ค่าใช้จ่ายดำเนินงาน (`operatingExpenses`), กำไรสุทธิ (`netProfit`) + มาร์จิ้นสุทธิ (`netMargin`), บรรทัดที่ขาดต้นทุน (`finance.missingCostLines`), และหมายเหตุคุณภาพข้อมูล (`dataQualityNotes`)

```
Copilot แจ้งกำไรสุทธิติดลบหรือมาร์จิ้นต่ำ?
│
├─ ขั้นแรกเสมอ: เช็กว่าข้อมูลครบไหม (อย่าด่วนสรุปว่าขาดทุนจริง)
│   │  Copilot มี dataQualityNotes และ finance.missingCostLines เตือนถ้าข้อมูลไม่ครบ
│   └─ มีสินค้าไม่มีราคาทุน (missingCostCount / missingCostLines > 0)?
│       ├─ ใช่ → ต้นทุนขายถูกประเมินผิด กำไรที่เห็น "ไม่จริง"
│       │       → ไปแก้ตามแผนผังข้อ 5 (สินค้าไม่มีราคาทุน) ก่อน แล้วดูกำไรใหม่
│       └─ ไม่ → ไปวิเคราะห์สาเหตุจริงด้านล่าง
│
├─ กรณี A: กำไรขั้นต้น (grossMargin) ก็ต่ำ → ปัญหาที่ "ต้นทุน vs ราคาขาย"
│   │  (ขายแล้วแทบไม่เหลือกำไรตั้งแต่ก่อนหักค่าใช้จ่าย)
│   │
│   ├─ ต้นทุนรับเข้าแพงขึ้น?
│   │   │  Copilot › purchasingIntelligence.costChanges โชว์สินค้าที่ต้นทุนเพิ่ง
│   │   │  เปลี่ยน (ทุนเดิม → ทุนใหม่ + % เปลี่ยน + ผู้ขาย)
│   │   └─► ขั้นถัดไป: ต่อรองผู้ขาย / หาผู้ขายสำรอง
│   │         → จัดซื้อ › ผู้จัดจำหน่าย (/purchases/suppliers) ทบทวนเงื่อนไข
│   │         → ระวัง: purchasingIntelligence บอก singleSupplierProducts /
│   │           concentrationRisk (พึ่งผู้ขายรายเดียวมากไป = เสี่ยงโดนขึ้นราคา)
│   │
│   └─ ราคาขายต่ำเกินไป / ส่วนลดเยอะเกิน?
│       └─► ขั้นถัดไป: ทบทวนราคาขายและโปรโมชัน
│             → แก้ราคาขายรายตัว: สินค้า › รายการสินค้า (/products) แก้สินค้า
│             → ทบทวนส่วนลด/โปรที่กดมาร์จิ้น: โปรโมชั่น (/promotions)
│             หมายเหตุ: ขณะนี้ระบบยังไม่มีหัวข้อคู่มือ "ปรับราคาเป็นชุด
│             (bulk price change)" ในศูนย์ช่วยเหลือ
│
├─ กรณี B: กำไรขั้นต้นโอเค แต่กำไรสุทธิ (netMargin) ต่ำ/ติดลบ → ปัญหาที่ "ค่าใช้จ่าย"
│   │  (operatingExpenses กินกำไรขั้นต้นหมด)
│   └─► ขั้นถัดไป: ตรวจและคุมค่าใช้จ่ายดำเนินงาน
│         → ดู/บันทึกรายจ่าย: รายงาน & การเงิน › บันทึกรายจ่าย (/finance/expenses)
│           (เช็กว่ามีรายจ่ายผิดปกติ เช่น ค่าเช่า/ค่าน้ำไฟ/เงินเดือน สูงผิดปกติ)
│         → ดูภาพ รายได้ − ต้นทุน − ค่าใช้จ่าย รวม:
│           รายงาน & การเงิน › กำไรขาดทุน (P&L) (/finance/pnl)
│
└─ อยากเห็นภาพรวมตัวเลขทั้งหมดเป็นรายเดือน
    └─► ขั้นถัดไป: เปิดรายงานสรุป (8 การ์ด KPI + ตาราง P&L รายเดือน)
          → ไปที่เมนู รายงาน & การเงิน › รายงานสรุป (/reports/summary)
            เลขสีแดงในคอลัมน์กำไร = เดือนนั้นขาดทุน
```

**สำคัญ:** Copilot ตอบได้ว่ากำไรเท่าไร/มาร์จิ้นเท่าไร และเตือนถ้าข้อมูลไม่ครบ แต่ **ขณะนี้ระบบยังไม่มีข้อมูล** การจัดอันดับกำไรรายสินค้าใน Copilot — ถ้าต้องการดูสินค้าทำกำไร/ขาดทุนรายตัว ให้ดูที่ รายงาน & การเงิน

## 4) สินค้าค้างสต็อก (Dead Stock) — ควรระบายของอย่างไร?

**สัญญาณจาก Copilot:** ถาม "สต็อก" แล้ว Copilot โชว์ "เงินทุนจม" หรือดูการ์ดสุขภาพสต็อก (`inventory.deadStockValue`)

**ข้อมูลที่ Copilot ใช้ (inventoryIntelligence):** สินค้าทุนจมสูงสุด (`topDeadCapital`: ชื่อ, จำนวนคงเหลือ `remaining`, มูลค่าจม `tiedValue`, ขายครั้งสุดท้าย `lastSold`, ไม่เคยขายเลย `neverSold`, จำนวนวันที่ไม่ขยับ `daysInactive`), สินค้าค้างเกิน (`overstockItems`: เกินกี่ชิ้น `overstockQty`, มูลค่า `capitalValue`), ยอดรวมทุนจม (`totalDeadCapitalValue`) และยอดรวมค้างเกิน (`totalOverstockValue`)

```
Copilot แจ้งมีเงินทุนจมในสินค้าค้างสต็อก?
│
├─ สินค้านั้น "ไม่เคยขายเลย" (neverSold = ใช่, lastSold ว่าง)
│   └─► ขั้นถัดไป: ตัดสินใจเด็ดขาด — ลดราคาระบาย หรือเลิกสต็อก
│         → ตั้งโปรลดราคา/ล้างสต็อก: โปรโมชั่น (/promotions)
│           กด "+ สร้างโปรโมชัน" → เลือกชนิด (%/บาท/ซื้อครบลด/ซื้อแถม/คอมโบ)
│         → ดูมูลค่าจมก่อนตัดสินใจ:
│           รายงาน & การเงิน › มูลค่าสต็อก & สินค้าค้าง (/reports/inventory-value)
│
├─ สินค้านั้น "เคยขายแต่ไม่ขยับนาน" (daysInactive สูง, มี lastSold)
│   └─► ขั้นถัดไป: เร่งระบายก่อนทุนจมนานกว่านี้
│         → ตั้งโปรกระตุ้นการขาย: โปรโมชั่น (/promotions)
│         → ตรวจอายุสินค้าค้าง 30/60/90 วัน เพื่อจัดลำดับลดราคา:
│           รายงาน & การเงิน › มูลค่าสต็อก & สินค้าค้าง (/reports/inventory-value)
│
├─ เป็น "ของค้างเกิน" (overstockItems — สต็อกเกิน maxStock)
│   └─► ขั้นถัดไป: หยุดสั่งเพิ่ม + ระบายส่วนเกิน
│         → อย่าเปิด PO รายการนี้: จัดซื้อ › การสั่งซื้อ (/purchases) ตรวจก่อนสั่ง
│         → ระบายส่วนเกินด้วยโปร: โปรโมชั่น (/promotions)
│
└─ อยากเห็นภาพรวมทุนจมทั้งร้าน
    └─► ขั้นถัดไป: เปิดรายงานมูลค่าสต็อก (มูลค่ารวม + สินค้าค้าง 30/60/90)
          → ไปที่เมนู รายงาน & การเงิน › มูลค่าสต็อก & สินค้าค้าง
            (/reports/inventory-value) — ส่งออก Excel ได้
```

**กฎง่าย ๆ:** เงินที่จมอยู่ในของขายไม่ออก = เงินที่เอาไปหมุนซื้อของขายดีได้ → ยิ่งจมนาน ยิ่งควรยอมลดราคาเพื่อเอาเงินสดคืน

## 5) สินค้าไม่มีราคาทุน (Missing Cost) — แก้ไขอย่างไร?

**สัญญาณจาก Copilot:** การ์ดสุขภาพสต็อก/การเงิน (`inventory.missingCostCount`, `finance.missingCostLines`) หรือ `moneyIntelligence.dataQualityNotes` เตือนว่ามีสินค้าขาดต้นทุน

**ทำไมต้องแก้ก่อน:** ถ้าสินค้าไม่มีราคาทุน ระบบคำนวณ **ต้นทุนขาย (COGS) และกำไรผิด** → ตัวเลขกำไร/มาร์จิ้นที่เห็นในข้อ 3 จะเชื่อถือไม่ได้

```
Copilot แจ้งมีสินค้าไม่มีราคาทุน (missingCost > 0)?
│
├─ รู้ว่าเป็นสินค้าตัวไหน
│   └─► ขั้นถัดไป: เติมราคาทุนเข้าไปในสินค้าโดยตรง
│         → ไปที่เมนู สินค้า › รายการสินค้า (/products)
│           เปิดสินค้า → "แก้ไข" → กรอก "ราคาทุน" ให้ถูกต้อง → บันทึก
│         (ราคาทุนมีผลต่อการคำนวณกำไรในรายงาน — กรอกให้แม่นยำ)
│
├─ มีหลายตัว / ไม่แน่ใจว่าตัวไหนบ้าง
│   └─► ขั้นถัดไป: ใช้รายงานช่วยไล่หา แล้วทยอยแก้
│         → ดูสินค้าและมูลค่าสต็อก:
│           รายงาน & การเงิน › มูลค่าสต็อก & สินค้าค้าง (/reports/inventory-value)
│         → ไล่แก้ราคาทุนทีละตัวที่ สินค้า › รายการสินค้า (/products)
│         หมายเหตุ: ขณะนี้ระบบยังไม่มีหัวข้อคู่มือเฉพาะสำหรับ "แก้ราคาทุนเป็นชุด"
│         แต่สามารถนำเข้า/อัปเดตหลายรายการผ่าน Excel ได้ (ดูด้านล่าง)
│
└─ ต้องการอัปเดตทีละมาก ๆ
    └─► ขั้นถัดไป: นำเข้าด้วย Excel (SKU ซ้ำจะอัปเดตของเดิมให้อัตโนมัติ)
          → ไปที่เมนู สินค้า › รายการสินค้า (/products) › "นำเข้า Excel"
            ดาวน์โหลดเทมเพลต → กรอกราคาทุน → อัปโหลด → ตรวจ preview → ยืนยัน
```

**กฎง่าย ๆ:** อย่าเชื่อตัวเลขกำไรจนกว่า `missingCost` จะเป็น 0 — แก้ราคาทุนให้ครบก่อน แล้วค่อยกลับไปอ่านกำไรในข้อ 3

## 6) ใบรับสินค้าค้างยืนยัน (Pending Goods Receipt) — จัดการอย่างไร?

**สัญญาณจาก Copilot:** ถาม "ทำอะไร/priorities" หรือการ์ดปฏิบัติการ (`operations.pendingReceiptsCount` > 0) — มีใบรับสินค้าที่รับของมาแล้วแต่ยังไม่ยืนยันเข้าระบบ

**ผลกระทบถ้าปล่อยค้าง:** สต็อกในระบบ **น้อยกว่าของจริง** → ระบบอาจเตือนสต็อกต่ำผิด ๆ และอาจไปสั่งซื้อซ้ำโดยไม่จำเป็น

```
Copilot แจ้งมีใบรับสินค้าค้างยืนยัน?
│
├─ ของมาถึงครบแล้ว ตรงกับที่สั่ง
│   └─► ขั้นถัดไป: ยืนยันรับเข้า เพื่อให้สต็อกเพิ่มทันที
│         → ไปที่เมนู จัดซื้อ / คลังสินค้า › รับสินค้าเข้า (/warehouse/receive)
│           เปิดใบรับที่ค้าง → ตรวจรายการ/จำนวน/ต้นทุน → "ยืนยันรับสินค้า"
│           (สต็อกจะเพิ่มขึ้นทันทีหลังยืนยัน)
│
├─ ใบรับเป็นฉบับร่าง ยังกรอกไม่ครบ (อยู่ระหว่างขั้นตอน step)
│   └─► ขั้นถัดไป: กรอกให้ครบทีละขั้นจนยืนยันได้
│         → รับสินค้าเข้า (/warehouse/receive) เปิดใบนั้น เดินตามขั้นตอน:
│           เลือกสินค้า → ตรวจจำนวน → สรุป/ยืนยัน
│
├─ ของมาไม่ครบ / จำนวนไม่ตรงกับ PO
│   └─► ขั้นถัดไป: แก้จำนวนรับจริงตามของที่ได้ แล้วค่อยยืนยัน
│         → รับสินค้าเข้า (/warehouse/receive) แก้จำนวนรับจริงต่อรายการ
│         → ตรวจ PO ต้นทางประกอบ: จัดซื้อ › การสั่งซื้อ (/purchases)
│
└─ อยากรู้ว่ามีใบไหนค้างบ้าง
    └─► ขั้นถัดไป: เปิดรายการใบรับทั้งหมด
          → ไปที่เมนู จัดซื้อ / คลังสินค้า › รับสินค้าเข้า (/warehouse/receive)
            ดูรายการใบรับ (GRN) ทั้งหมดและสถานะ
```

**หมายเหตุ:** Copilot **ยืนยันรับสินค้าให้แทนไม่ได้** (ฟังก์ชันสั่งงานยังขึ้น "เร็ว ๆ นี้") — ต้องไปกดยืนยันเองในเมนูรับสินค้าเข้า

## 7) ภาพรวมสุขภาพร้าน — ควรทำอะไรก่อน?

**สัญญาณจาก Copilot:** ถาม "ภาพรวม / สุขภาพ / สรุป / ทำอะไรดี" — Copilot ให้คะแนนสุขภาพรวม 0–100 และจัดลำดับงานสำคัญ

**ข้อมูลที่ Copilot ใช้:** คะแนนรวม (`healthScore.overall`) แยกเป็น ขาย / สต็อก / การเงิน / ปฏิบัติการ, เครื่องจัดลำดับงาน (`decisionEngine`: `topPriority`, `todayPriorities`, `weekPriorities` — แต่ละงานมีเหตุผล `reason` และป้ายความเร่งด่วน `urgencyLabel`), รายการความเสี่ยง (`risks` แบ่งระดับ critical/high/medium/low) และโอกาส (`opportunities`)

```
Copilot โชว์คะแนนสุขภาพร้าน + งานที่ควรทำ
│
├─ มีงาน "ทำวันนี้" (todayPriorities) จาก decisionEngine
│   └─► ขั้นถัดไป: ทำตามลำดับที่ระบบจัดให้ (เรียงตามผลกระทบ + เหตุผล)
│         → กดปุ่ม action ในการ์ด Copilot เพื่อกระโดดไปหน้าที่เกี่ยว (route)
│         → ถามต่อ "ถ้าไม่ทำจะเป็นยังไง" เพื่อดูผลกระทบ
│         → ถามต่อ "ควรทำวันนี้ไหม" เพื่อดูระดับเร่งด่วน
│           (🔴 ทันที / 🟡 วันนี้ / 🟢 สัปดาห์นี้)
│
├─ ปัญหาหลักอยู่หมวด "สต็อก" (inventory.score ต่ำ)
│   └─► ไปแผนผังข้อ 1 (สต็อกต่ำ) / ข้อ 4 (สินค้าค้าง) / ข้อ 5 (ไม่มีราคาทุน)
│
├─ ปัญหาหลักอยู่หมวด "การเงิน" (finance.score ต่ำ)
│   └─► ไปแผนผังข้อ 3 (กำไรติดลบ/ต่ำ)
│
├─ ปัญหาหลักอยู่หมวด "ปฏิบัติการ" (operations.score ต่ำ)
│   └─► ลูกหนี้เกินกำหนด → แผนผังข้อ 2
│       ใบรับสินค้าค้าง → แผนผังข้อ 6
│
└─ Copilot โชว์ "โอกาส" (opportunities) ไม่ใช่แค่ปัญหา
    └─► ขั้นถัดไป: อ่านคำแนะนำ (recommendation) + ตัวเลขประกอบ (metric)
          แล้วลงมือในเมนูที่เกี่ยวข้อง (เช่น โปรโมชั่น, สินค้า, จัดซื้อ)
```

**ข้อจำกัดที่ควรรู้:** Copilot **บอกได้ว่างานไหนสำคัญและเพราะอะไร** (จาก `reason`) แต่ **อธิบายไม่ได้ว่าระบบหลังบ้านคำนวณคะแนนมายังไงทีละขั้น** และ **ขณะนี้ระบบยังไม่มีข้อมูล** การจัดอันดับยอดขายรายสินค้าใน Copilot — สินค้าที่โชว์ว่า "ขายดี" คือสินค้าที่หมุนเร็วจากรายการเติมด่วน (อัตราขายต่อวัน) ไม่ใช่อันดับยอดขายจริง ให้ดูอันดับจริงที่ รายงาน & การเงิน › รายงานสรุป (/reports/summary)

## ภาคผนวก — วิธีคุยกับ Copilot ให้ได้คำตอบตรงจุด

> Copilot ใช้ **การจับคำสำคัญ (keyword)** ไม่ใช่ AI พิมพ์ตอบอิสระ — ใช้คำให้ตรงหมวดจะได้คำตอบแม่นกว่า

| อยากรู้เรื่อง | พิมพ์คำประมาณนี้ | Copilot ตอบอะไร |
|---|---|---|
| ยอดขาย | ยอด, ขาย, revenue | รายได้ 7 วัน, วันนี้, ยอดเฉลี่ยต่อบิล, จำนวนออเดอร์ |
| กำไร | กำไร, ขาดทุน, margin, profit | P&L 7 วัน + วันนี้, ขั้นต้น/สุทธิ + ป้ายสถานะ |
| สต็อก | สต็อก, ใกล้หมด, reorder, หมด | สินค้าหมด/ใกล้หมด, เติมด่วน 3 อันดับ, ทุนจม |
| ลูกหนี้ | ลูกหนี้, ค้างชำระ, เก็บเงิน, overdue | ยอดค้าง, กลุ่มอายุหนี้, ลูกหนี้เกินกำหนด 3 ราย |
| จัดซื้อ | ซื้อ, สั่งซื้อ, ซัพ, supplier, ต้นทุน | ยอดซื้อรวม, ความเสี่ยงพึ่งผู้ขายรายเดียว, PO ค้าง, ต้นทุนที่เปลี่ยน |
| ความเสี่ยง | ความเสี่ยง, ปัญหา, risk | รายการความเสี่ยง 5 อันดับ |
| โอกาส | โอกาส, เติบโต, improve | รายการโอกาส + ตัวเลข + คำแนะนำ |
| ควรทำอะไร | ทำอะไร, ควรทำ, สำคัญ, urgent | งานวันนี้ 3 อันดับ + งานสัปดาห์นี้ 2 อันดับ |
| ภาพรวม | ภาพรวม, สุขภาพ, สรุป | คะแนนร้าน 0–100 + สรุปสต็อก/ความเสี่ยง |
| ใครแก้ข้อมูล | ใครแก้, ใครเปลี่ยน, activity | ประวัติการแก้ไข: เปลี่ยนราคา, ลบ, แก้สำคัญ (ดูเต็มที่ ตั้งค่า › บันทึกกิจกรรม) |
| วิธีใช้งาน | วิธี, คู่มือ, how to, ทำไง | ค้นจากศูนย์ช่วยเหลือ: ขั้นตอน + เคล็ดลับ (เนื้อหาภาษาไทย) |

**สิ่งที่ Copilot ทำไม่ได้ (ขอบเขตระบบ):**
- สั่งงานแทนไม่ได้ (สร้าง PO / ปรับสต็อก / รับชำระ / ยืนยันรับของ) → ขึ้น "เร็ว ๆ นี้" ต้องทำเองในเมนู
- ไม่มีการจัดอันดับยอดขายรายสินค้าใน Copilot → ดูที่ รายงาน & การเงิน › รายงานสรุป
- ตอบเฉพาะภาพรวม **วันนี้ / 7 วันล่าสุด** — ขณะนี้ระบบยังไม่มีข้อมูลแนวโน้ม 30 วัน / เทียบปีต่อปีใน Copilot
- กรองข้อมูลเองตามวันที่/พนักงาน/หมวดใน Copilot ไม่ได้ → ใช้ตัวกรองในหน้ารายงานแทน
- เนื้อหาคู่มือ (ศูนย์ช่วยเหลือ) เป็นภาษาไทยเท่านั้น
