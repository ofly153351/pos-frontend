# AI Copilot — รูปแบบบทสนทนา (Conversation Patterns)

> เอกสารอ้างอิงสำหรับทีมที่ออกแบบ/เขียนคำตอบของ "ผู้ช่วยอัจฉริยะ" (Copilot) ในระบบ POS Today
> ภาษาหลัก: ไทย (เจ้าของร้านคนไทย) — ใช้ชื่อเมนูจริงจากระบบเสมอ

---

## ⚠️ กติกาเหล็ก (อ่านก่อนเขียนทุกครั้ง)

Copilot ตัวนี้ **ไม่ใช่ AI สร้างข้อความ (ไม่มี LLM)** — ทุกคำตอบมาจาก
**ตัวจัดเส้นทางตามคำสำคัญ (keyword router) + แม่แบบข้อความ (template)** ล้วน ๆ
ดังนั้นทุกประโยคในบทสนทนาต้อง **อิงข้อมูลจริง** ที่ระบบมีเท่านั้น:

- ตัวเลขธุรกิจ → มาจากชุดข้อมูล `CopilotOverview` (เรียกครั้งเดียวผ่าน `/api/stores/{storeId}/copilot`)
- เนื้อหา "วิธีทำ" → มาจากคลังหัวข้อช่วยเหลือ `lib/help/help-topics.ts` (ภาษาไทยเท่านั้น)
- ชื่อเมนู/หน้าจอ → ต้องตรงกับ Sidebar จริง (ดูตาราง "ชื่อเมนูจริง" ด้านล่าง)

**ถ้าข้อมูล/ฟีเจอร์ไหนไม่อยู่ในระบบ → ห้ามแต่งขึ้นมา** ให้ตอบว่า
`ขณะนี้ระบบยังไม่มีข้อมูลส่วนนี้` หรือเลี่ยงไม่พูดถึง

## 🎯 ภาพรวม 15 เจตนา (Intent) ที่ router รู้จัก

ทุกบทสนทนาต้องตกลงในเจตนาใดเจตนาหนึ่งต่อไปนี้ ถ้าไม่ตรงคำสำคัญใด → ตกไปที่ **fallback**

`greeting` · `thanks` · `sales` · `profit` · `stock` · `aging` · `stock+purchasing` ·
`risks` · `opportunities` · `priorities/actions` · `overview` · `best-sellers` ·
`consequence` · `urgency` · `activity` · `help` · `fallback`

> หมายเหตุ: Copilot จำ "หัวข้อล่าสุด + รายการล่าสุด (สูงสุด 3)" เพื่อให้คำถามต่อเนื่อง
> เช่น "ทำไม" / "อันนี้" / "ตัวแรก" / "เมื่อกี้" อ้างถึงได้ถูกต้อง

# 🧩 รูปแบบบทสนทนา (Conversation Patterns)

แต่ละรูปแบบมี: นิยาม → เมื่อไรใช้ → กติกาเฉพาะ → ตัวอย่างบทสนทนาจริง

---

## ① ทักทาย (Greeting)

**นิยาม:** เปิดบทสนทนา เมื่อผู้ใช้พิมพ์ทักทาย (intent `greeting`)
**คำสำคัญ:** สวัสดี, หวัดดี, hello, hi, hey
**กติกา:** ตอบสั้น เป็นมิตร แล้ว **เสนอคำถามเริ่มต้น (starter) 4 ข้อ** ที่ระบบตอบได้จริง
ห้ามถามชื่อ/สัพเพเหระ — เข้าเรื่องธุรกิจทันที

```
👤  สวัสดีครับ
🤖  สวัสดีครับ ผมเป็นผู้ช่วยร้านของคุณ
    ลองถามเรื่องเหล่านี้ได้เลยครับ
      • วันนี้ขายได้เท่าไหร่
      • มีสินค้าใกล้หมดไหม
      • ใครค้างชำระอยู่บ้าง
      • วันนี้ควรทำอะไรก่อน
```

> ✅ ทุกปุ่ม starter ต้องชี้ไปยังเจตนาที่ระบบตอบได้ (sales / stock / aging / priorities)

---

## ② สอบถามให้ชัด (Clarification)

**นิยาม:** เมื่อคำถามกำกวมจน "หน้าจอ/ตัวเลข" ที่ต้องตอบไม่เหมือนกัน ให้ถามกลับ 1 คำถามก่อน
**ตัวอย่างคลาสสิก:** "ของหมด" → หมายถึง **หน้าร้าน (จุดขาย)** หรือ **โกดัง (คลัง)**?
**กติกา:** ถามแบบมีตัวเลือกชัด อย่าถามปลายเปิด — ให้ผู้ใช้กดเลือกได้เลย

```
👤  ของหมดแล้วเหรอ
🤖  หมายถึงตรงไหนครับ ขอแยกให้ชัดก่อน
      • หน้าร้าน (จุดขาย) — ของที่พร้อมขายตอนนี้
      • โกดัง (คลังสินค้า) — สต็อกที่เก็บไว้รวม
    เลือกได้เลยครับ เดี๋ยวผมดึงตัวเลขให้

👤  หน้าร้าน
🤖  ตอนนี้ "หน้าร้าน" มีสินค้าหมดสต็อก 3 รายการ และใกล้หมด 5 รายการ
    ดูรายการเต็มได้ที่เมนู "สต็อกสินค้า" ครับ
```

> ⚠️ ระบบมีตัวเลข `inventory.outOfStockCount` และ `inventory.lowStockCount` รวมของร้าน
> ถ้าระบบ **แยกหน้าร้าน/โกดังไม่ได้ในชุดข้อมูล Copilot** → ตอบรวม แล้วบอกให้ไปดูแยกที่เมนู
> "สต็อกสินค้า" / "แดชบอร์ดคลัง" (อย่าแต่งตัวเลขแยกขึ้นมาเอง)

---

## ③ อธิบาย (Explain)

**นิยาม:** อธิบายว่าตัวเลข/สถานะหนึ่ง ๆ คืออะไร — ตอบตรง ไม่อ้อม
**กติกา:** ใช้ค่าจริงจาก `summary` / `moneyIntelligence` / `healthScore`
ถ้าผู้ใช้ถามถึง **วิธีคำนวณภายใน backend** → ตอบได้แค่ "ความหมาย" ไม่ใช่ "สูตรหลังบ้าน"

```
👤  ขายเชื่อในแดชบอร์ดหมายความว่าไง
🤖  "ขายเชื่อ" คือยอดที่ลูกค้าซื้อไปแล้วแต่ยังไม่จ่ายเงิน (เป็นลูกหนี้ของร้าน)
    ในแดชบอร์ดจะแสดงด้วยสีส้ม เพื่อแยกจากยอดเงินสดสีม่วง
    ดูใครค้างอยู่บ้างได้ที่เมนู "ขายเชื่อ / ยืม" ครับ

👤  แล้วกำไรขั้นต้นล่ะ
🤖  กำไรขั้นต้น (Gross Profit) = ยอดขาย − ต้นทุนสินค้าที่ขายไป (COGS)
    ช่วง 7 วันล่าสุดของร้านคุณอยู่ที่อัตรากำไรขั้นต้น {grossMargin}%
    ดูแบบเต็มเป็นรายเดือนได้ที่ "กำไรขาดทุน (P&L)" ครับ
```

> ✅ ค่าที่ใช้ได้: `summary.revenue`, `summary.netProfit`, `summary.netMargin`,
> `moneyIntelligence.grossMargin/grossProfit/cogs/operatingExpenses`
> ❌ ห้ามอธิบายว่า backend คำนวณคะแนน/สูตรอย่างไร (`ขณะนี้ระบบยังไม่มีข้อมูลส่วนนี้`)

## ④ สอนงาน (Teach — โค้ชเวิร์กโฟลว์)

**นิยาม:** ผู้ใช้ถาม "ทำยังไง / วิธี / step by step" (intent `help`)
**กติกา:** ดึงเนื้อหาจากคลัง `help-topics.ts` เท่านั้น — คืน **ขั้นตอน + เคล็ดลับ + ชื่อหมวด**
เนื้อหาช่วยเหลือ **เป็นภาษาไทยเท่านั้น** — ถ้าถามเป็นอังกฤษจะได้รายการ fallback ไม่มีขั้นตอนละเอียด

```
👤  พักบิลยังไง
🤖  📂 หมวด: ขายสินค้า (POS) — "พักบิล"
    เก็บตะกร้าไว้ชั่วคราวเพื่อไปบริการลูกค้ารายอื่น แล้วค่อยกลับมาทำต่อ
    ขั้นตอน:
      1. กดไอคอนเมนู (⋮) บนตะกร้า
      2. กด "พักบิล" แล้วตั้งชื่อโต๊ะ/ลูกค้า
      3. ตะกร้าถูกเก็บ พร้อมรับออเดอร์ใหม่
      4. กดไอคอน "บิลที่พักไว้" (📋) ด้านบนเพื่อเรียกคืน
      5. กด "ขายต่อ"
    เปิดเมนู "หน้าขาย" เพื่อเริ่มได้เลยครับ
```

ตัวอย่างถามเป็นอังกฤษ (เนื้อหาไทยเท่านั้น):

```
👤  how do I hold a bill?
🤖  คู่มือมีเป็นภาษาไทยครับ ลองถามว่า "พักบิลยังไง" จะได้ขั้นตอนแบบละเอียด
    หรือเลือกหัวข้อด้านล่างนี้ได้เลย
      • ขายสินค้า (POS)  • คลังสินค้า  • เอกสาร  • รายงาน & การเงิน
```

> ✅ หัวข้อที่สอนได้ มาจาก 11 หมวดในคลังช่วยเหลือ เช่น: เริ่มต้นใช้งาน, แดชบอร์ด,
> ขายสินค้า (POS), ขายเชื่อ, เอกสาร, สินค้า, คลังสินค้า, จัดซื้อ, ลูกค้า & โปรโมชัน,
> รายงาน & การเงิน, ตั้งค่า
> ❌ เวิร์กโฟลว์ที่ **ยังไม่มีหัวข้อในคลัง** (เช่น โอนสต็อกระหว่างคลัง, ปิดยอดสิ้นวัน,
> คืนสินค้าจากลูกค้า, คืนของให้ซัพพลายเออร์) → `ขณะนี้ระบบยังไม่มีข้อมูลส่วนนี้`

## ⑤ เปรียบเทียบ (Compare)

**นิยาม:** วางตัวเลขสองค่าให้เห็นชัด เช่น วันนี้เทียบช่วงก่อน หรือลูกค้าค้างชำระสูงสุดสองราย
**กติกา:** เปรียบเทียบได้เฉพาะค่าที่ "มีจริงในชุดข้อมูล" เท่านั้น
ระบบมีแค่ **วันนี้** กับ **7 วันล่าสุด** + ค่าเปลี่ยนแปลง — **ไม่มี 30 วัน / YoY / เทรนด์ระยะยาว**

```
👤  วันนี้ขายดีกว่าเมื่อวานไหม
🤖  เทียบแบบนี้ได้ครับ
      • ยอดขายวันนี้: ฿{revenueToday}  ({revenueTodayChange:+%} เทียบช่วงก่อน)
      • กำไรวันนี้:   ฿{profitToday}
    ส่วนภาพรวม 7 วันล่าสุด ยอดรวม ฿{revenue} ({revenueChange:+%})
    ถ้าอยากดูเทียบรายเดือนแบบเต็ม ให้เปิด "รายงานสรุป" ครับ

👤  แล้วเทียบเดือนที่แล้วล่ะ
🤖  ผู้ช่วยมีข้อมูลแค่ "วันนี้" กับ "7 วันล่าสุด" ครับ
    การเทียบรายเดือนต้องดูที่เมนู "รายงานสรุป" ซึ่งมีตาราง P&L รายเดือนให้ครับ
```

> ✅ ใช้: `revenueToday`, `revenueTodayChange`, `profitToday`, `revenue`, `revenueChange`
> ❌ 30 วัน / ไตรมาส / ปีต่อปี ในแชต = `ขณะนี้ระบบยังไม่มีข้อมูลส่วนนี้` → ส่งไป "รายงานสรุป"/"P&L"

## ⑥ แนะนำ (Recommend — พร้อมเหตุผล "ทำไม")

**นิยาม:** เสนอสิ่งที่ควรทำ พร้อม **เหตุผลที่ชัด** เสมอ (intent `priorities/actions`, `opportunities`, `stock`)
**กติกา:** ใช้ `decisionEngine` (มี `reason`, `urgencyLabel`, `score`) และ `inventoryIntelligence.reorderRecommendations` (มี `reasonTh`, ค่าแนะนำ purchase / wait_for_po / transfer)
**ทุกคำแนะนำต้องมี "เพราะ..."** — ห้ามแนะนำลอย ๆ

```
👤  วันนี้ควรทำอะไรก่อน
🤖  สิ่งที่ควรทำวันนี้ (เรียงตามผลกระทบ):
      1. 🔴 สั่งซื้อ "{productName}" เพิ่ม
         เพราะ เหลือพอขายอีกแค่ {daysOfStock} วัน และยังไม่มี PO ค้างอยู่
         → แนะนำสั่ง {reorderQty} ชิ้น  (ไปที่ "การสั่งซื้อ (PO)")
      2. 🟡 ตามเก็บหนี้ "{customerName}"
         เพราะ ค้างชำระ ฿{outstanding} เกินกำหนด {daysOverdue} วันแล้ว
         → ไปที่ "ขายเชื่อ / ยืม"
    สัปดาห์นี้ค่อยทำ: ทบทวนสต็อกค้าง (dead capital ฿{totalDeadCapitalValue})
```

ตัวอย่างคำแนะนำสต็อกที่ "ไม่ใช่สั่งซื้อ":

```
👤  {productName} ใกล้หมดแล้วสั่งเพิ่มดีไหม
🤖  ยังไม่ต้องสั่งใหม่ครับ — แนะนำ "รอของจาก PO"
    เพราะ มี PO ค้างอยู่แล้ว {pendingPOQty} ชิ้น พอรับเข้าจะกลับมาเพียงพอ
    ({reasonTh})
```

> ✅ `decisionEngine.topPriority/todayPriorities/weekPriorities` (action + score + reason + urgencyLabel)
> ✅ `reorderRecommendations[].recommendation` = purchase | wait_for_po | transfer (+ `reasonTh`)
> ✅ `opportunities[]` ต้องโชว์ `recommendation` + `metric` คู่กัน

## ⑦ เตือน (Warn — บอกผลที่ตามมา)

**นิยาม:** เตือนถึง "ถ้าไม่ทำจะเกิดอะไร" (intent `consequence`) — ตอบตามบริบทล่าสุดที่จำไว้
**คำสำคัญ:** ถ้าไม่ทำ, what happens if ignored
**กติกา:** บอกผลกระทบจริง (ของหมด → เสียยอดขาย, หนี้ค้าง → กลายเป็นหนี้สูญ) + กรอบเวลา
อิงค่าที่มี เช่น `daysOfStock`, `daysOverdue`, `tiedValue` — ห้ามขู่เกินจริง

```
👤  ถ้าไม่สั่ง {productName} ตอนนี้จะเป็นไง
🤖  ⚠️ ถ้าปล่อยไว้:
      • ของจะหมดภายใน ~{daysOfStock} วัน (ขายเฉลี่ยวันละ {avgDailySales} ชิ้น)
      • หมดแล้ว = ขายไม่ได้ → เสียยอดขายช่วงนั้น และลูกค้าอาจไปซื้อที่อื่น
    แนะนำเปิด PO วันนี้เลยครับ ไปที่ "การสั่งซื้อ (PO)"

👤  แล้วลูกหนี้รายนั้นที่ค้างอยู่ล่ะ ถ้าไม่ตามจะเป็นไง
🤖  ⚠️ {customerName} ค้าง ฿{outstanding} มา {daysOverdue} วันแล้ว
      • ยิ่งทิ้งไว้นาน โอกาสกลายเป็น "หนี้สูญ" ยิ่งสูง
      • เงินก้อนนี้คือสภาพคล่องที่ร้านควรได้คืน
    ควรโทรตามภายในสัปดาห์นี้ครับ
```

> ✅ ผลกระทบต้องผูกกับค่าจริง (`urgentReorders[]`, `agingCustomers[]`, `topDeadCapital[]`)
> ⚠️ Warn ทำงานได้ดีเมื่อ "มีรายการอยู่ในบริบท" จากเทิร์นก่อน (multi-turn memory)

## ⑧ สรุป (Summarize)

**นิยาม:** ภาพรวมสุขภาพร้านแบบกระชับ (intent `overview`)
**คำสำคัญ:** overview, health, ภาพรวม, สุขภาพ, สรุป
**กติกา:** ใช้ `healthScore` (overall 0–100 + 4 ด้าน) + snapshot วันนี้ — ไม่ลงรายละเอียดยิบ

```
👤  สรุปภาพรวมร้านให้หน่อย
🤖  📊 สุขภาพร้านวันนี้: {overall}/100
      • ยอดขาย: {sales.score}/100  (7 วัน ฿{revenue}, {revenueChange:+%})
      • สต็อก:  {inventory.score}/100  (หมด {outOfStockCount} / ใกล้หมด {lowStockCount} รายการ)
      • การเงิน: {finance.score}/100  (กำไรสุทธิ ฿{netProfit}, มาร์จิน {netMargin}%)
      • งานค้าง: {operations.score}/100  (รับของค้าง {pendingReceiptsCount}, หนี้เกินกำหนด {overdueCreditCount} ราย)
    วันนี้: ขายไป ฿{revenueToday}, กำไร ฿{profitToday}
    อยากเจาะด้านไหนบอกได้เลยครับ
```

> ✅ ทั้งหมดมาจาก `healthScore.*` + `summary.revenueToday/profitToday`
> สรุปคือ "ชี้จุด" แล้วชวนเจาะต่อ — ไม่ใช่ยำทุกตัวเลข

## ⑨ จำข้ามเทิร์น (Multi-turn Memory)

**นิยาม:** เข้าใจคำอ้างอิงย้อนหลัง — **มัน / อันนี้ / ตัวแรก / เมื่อกี้ / ทำไม / บอกเพิ่ม**
**กติกา:** Copilot เก็บ "หัวข้อล่าสุด + รายการล่าสุด (สูงสุด 3)" คำอ้างอิงต้อง resolve กับรายการนั้น
ถ้าไม่มีบริบทค้างไว้ → ถามกลับให้ชัด (อย่าเดา)

```
👤  มีสินค้าใกล้หมดไหม
🤖  มีรายการเร่งด่วน 3 ตัวครับ
      1. {productName_A} — เหลือพอขาย {daysOfStock_A} วัน
      2. {productName_B} — เหลือพอขาย {daysOfStock_B} วัน
      3. {productName_C} — เหลือพอขาย {daysOfStock_C} วัน

👤  ตัวแรกสั่งเท่าไหร่ดี
🤖  "{productName_A}" แนะนำสั่ง {reorderQty_A} ชิ้น
    เพราะขายเฉลี่ยวันละ {avgDailySales_A} ชิ้น และของจะหมดใน {daysOfStock_A} วัน

👤  แล้วมันมี PO ค้างอยู่ไหม
🤖  "{productName_A}" {hasPendingPO ? "มี PO ค้างอยู่ " + pendingPOQty + " ชิ้น" : "ยังไม่มี PO ค้างเลยครับ"}

👤  ทำไมต้องรีบ
🤖  เพราะถ้าไม่สั่ง ของจะหมดใน {daysOfStock_A} วัน แล้วช่วงนั้นจะขายไม่ได้
    (อ้างจากรายการ "{productName_A}" ที่เราคุยกันเมื่อกี้)
```

กรณีไม่มีบริบทค้าง:

```
👤  อันนี้สั่งเท่าไหร่ดี
🤖  ขอโทษครับ ยังไม่แน่ใจว่า "อันนี้" หมายถึงสินค้าตัวไหน
    ลองถาม "มีสินค้าใกล้หมดไหม" ก่อน แล้วค่อยบอกว่าจะดูตัวไหนได้เลยครับ
```

> ✅ จำได้สูงสุด 3 รายการ + หัวข้อล่าสุด — เพียงพอกับ "ตัวแรก/ตัวที่สอง/อันนี้/เมื่อกี้"
> ❌ ถ้าผู้ใช้อ้างถึงรายการที่ 4+ หรือบริบทเก่าเกิน → ถามกลับ ไม่เดา

## ⑩ ปิดบทสนทนา (Close)

**นิยาม:** ปิดอย่างสุภาพเมื่อผู้ใช้ขอบคุณ/จบงาน (intent `thanks`)
**คำสำคัญ:** ขอบคุณ, ขอบใจ, thank, thx
**กติกา:** ตอบรับสั้น + เสนอ starter 4 ข้อ เผื่ออยากทำต่อ — ไม่ยืดเยื้อ

```
👤  โอเค ขอบคุณมาก
🤖  ยินดีครับ 🙏 ถ้ามีอะไรเพิ่มถามได้เลย
      • วันนี้ขายได้เท่าไหร่
      • มีสินค้าใกล้หมดไหม
      • ใครค้างชำระอยู่บ้าง
      • วันนี้ควรทำอะไรก่อน
```

# 🚫 สิ่งที่ Copilot ทำไม่ได้ (ต้องตอบให้ถูกเมื่อเจอ)

ออกแบบคำตอบให้ "ปฏิเสธอย่างมีประโยชน์" — บอกว่าทำไม่ได้ แล้วชี้ทางไปทำเองที่เมนูจริง

| ผู้ใช้ขอ | Copilot ตอบแนวนี้ |
|---------|------------------|
| "สร้าง PO ให้หน่อย" / สั่งให้ทำงานแทน | "ผู้ช่วยยังสั่งงานแทนไม่ได้ครับ (กำลังพัฒนา) — เปิด PO เองได้ที่ 'การสั่งซื้อ (PO)'" |
| "สินค้าตัวไหนขายดีที่สุด" (อันดับยอดต่อชิ้น) | "ผู้ช่วยไม่มีอันดับยอดขายต่อสินค้าครับ — มีแค่ตัว 'ขายเร็ว' จากความเร็วการขาย ดูอันดับเต็มที่ 'รายงานสรุป'" |
| ถามนอกเรื่อง / คุยเล่น | ตกไป fallback: "ลองถามเรื่องเหล่านี้ได้ครับ…" + 6 ปุ่มหัวข้อ |
| ขอเทรนด์ 30 วัน / ปีต่อปี | "ผู้ช่วยมีแค่วันนี้กับ 7 วันล่าสุด — ดูรายเดือนที่ 'รายงานสรุป' / 'P&L'" |
| คู่มือภาษาอังกฤษแบบละเอียด | เนื้อหาช่วยเหลือเป็นภาษาไทยเท่านั้น → เสนอถามใหม่เป็นไทย |

ตัวอย่าง "ขายดีที่สุด" (intent `best-sellers` — เป็น proxy ความเร็วการขาย ไม่ใช่อันดับยอด):

```
👤  สินค้าตัวไหนขายดีที่สุด
🤖  ผู้ช่วยยังไม่มี "อันดับยอดขายต่อสินค้า" โดยตรงครับ
    แต่บอก "สินค้าที่ขายเร็ว" ให้ได้ (จากอัตราการขายเฉลี่ยต่อวัน):
      1. {productName_A} — เฉลี่ย {avgDailySales_A} ชิ้น/วัน
      2. {productName_B} — เฉลี่ย {avgDailySales_B} ชิ้น/วัน
    อยากได้อันดับยอดขายแบบเต็ม ให้เปิด "รายงานสรุป" ครับ
```

ตัวอย่าง "สั่งงานแทน" (ทุก action = กำลังพัฒนา):

```
👤  เปิดบิลขายเชื่อให้ลูกค้า A หน่อย
🤖  ผู้ช่วยยังเปิดบิลแทนไม่ได้ครับ (ฟีเจอร์สั่งงานกำลังพัฒนา)
    เปิดเองได้ง่าย ๆ ที่ "หน้าขาย" → "ชำระเงิน" → แท็บ "เปิดบิลเชื่อ" ครับ
```

# 🧠 ปัญญาเฉพาะเรื่องที่ตอบได้ (อ้างชุดข้อมูลให้ตรง)

| เจตนา | ตอบอะไรได้ (ชุดข้อมูลจริง) |
|------|---------------------------|
| `sales` | ยอด 7 วัน, ยอดวันนี้, AOV (`averageOrderValue`), จำนวนออเดอร์ (`orders`) |
| `profit` | P&L 7 วัน + วันนี้, gross/net/operating, ป้ายสถานะ |
| `stock` | หมด/ใกล้หมด, สั่งซื้อด่วน top 3, ทุนจม (dead capital), ทิปคลัง |
| `aging` | ยอดค้างรวม, ช่วงอายุหนี้ (30/60/90/90+), ลูกหนี้เกินกำหนด top 3 |
| `stock+purchasing` | ยอดซื้อรวม, จำนวนซัพ, ความเสี่ยงกระจุกตัว, PO ค้าง, ซัพ top 3, ต้นทุนที่เปลี่ยน |
| `risks` | รายการความเสี่ยง top 5 (จัดกลุ่มตามความรุนแรง) |
| `opportunities` | โอกาสทั้งหมด (title + metric + recommendation) |
| `activity` | ใครแก้ราคา/ลบ/แก้สำคัญ (ดึงจากบันทึกกิจกรรม แบบ async) |

ตัวอย่าง `activity` (เชื่อมกับเมนู "บันทึกกิจกรรม"):

```
👤  ใครแก้ราคาสินค้า {productName}
🤖  จากบันทึกกิจกรรม:
      • {userName} แก้ราคา "{productName}"  จาก ฿{before} → ฿{after}  เมื่อ {when}
    ดูไทม์ไลน์เต็ม + ก่อน/หลัง ได้ที่ "บันทึกกิจกรรม" (Settings) ครับ
```

> ⚠️ ฟิลด์ที่ "อาจว่าง/null": `risks[].actionRoute`, `opportunities[].metric`,
> `topDeadCapital[].lastSold` (null = ไม่เคยขาย), `actions[].impactValue/badge`
> ถ้าฟิลด์ว่าง → ข้ามไป อย่าโชว์ค่าว่าง และเคารพ `moneyIntelligence.dataQualityNotes[]`
> (เตือนผู้ใช้เมื่อข้อมูลไม่ครบ เช่น ต้นทุนสินค้าหาย / รับของไม่ครบ)

# ✅ เช็กลิสต์ก่อนปล่อยคำตอบ (ทุกรูปแบบ)
